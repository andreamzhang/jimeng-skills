# 短剧人物资产建库（即梦分镜师 · 阶段零点五）

## 使用场景

- 新剧要建 `scripts/<剧名>/assets/character-prompts.md`；或既有剧要补人物/加状态变体。
- 用户说「人物资产跑一下」「按统一口径建人物库」时。

不适用：单集分镜生产（AGENTS.md 阶段一～八）；场景/道具库（同流程，见末节）。

**工作区根**：Codex 项目根（AGENTS.md 所在目录）。所有 `scripts/…`、`tools/…`、`config/…` 相对该根。
**前置**：剧本已拆集（`scripts/<剧名>/script/epXX.txt`）＋ 本剧身份记忆文件存在。

## 输出格式（唯一口径 · 2026-10-09 起生效）

按 `templates/character-entry.md` 输出，每套路人一块，跨集复用同一格式。
关键口径：
1. 出图要求固定为「竖屏9:16，纯白背景，上1下3四格排版，分割构图…」，一字不改。
2. 每位角色一段，不得多人合并到同一段。
3. 面部/服装细节要具体；服装按“款式 + 颜色 + 材质 + 细节”逐件写全。
4. 画质要求固定为“真人实拍质感”那一段，不得换风格。
5. 负面口径统一用「避免：多余头部、错误人体结构、多手多脚、服装不一致」。
6. 严禁重新引入旧版“骨相/锚定句/库路线”等历史口径。

## 人物拆分与未写明项（2026-10-11 起生效）

1. **主要角色**：按职业、服装、伤势、年龄阶段、破产前后状态等可见维度分条，同一人
   职业或身体/财产状态发生变化时，对每个需要重点区分的状态建独立条目，不再硬凑成
   一条包干。
2. **可见次要角色与群像**：不逐人建独立条目；按职能归组（保安、客户、员工、打手、
   护士、投资人、股东、董事等），共用一条角色资产。
3. 只写剧本明确写到的年龄、身份、服装、伤势与可见状态；剧本未写明的五官、肤色、
   发型/发色、精确身高不得推定，写「未限定」或直接省略。
4. 曾在既有资产库出现的“未在剧情说明的五官、肤色、发型等不作额外限定”短语是同一
   条宽化口径，继续沿用；不要为了凑满字段而补风格猜测。
5. 次要/一次性配角：如果没有剧本明确要求换装，或没有明显的换服装/状态暗示，
   不得为了拆形态而增加条目；核心/重要配角才扩展状态变体。

## 建库流程

1. 清点：`python tools/gen_character_inventory.py "<剧名>"` 产出 `assets/_character-inventory.md`。
2. 派美术子代理按 `templates/character-entry.md` 生成各角色提示词，直接写入 `assets/character-prompts.md`。
3. 状态变体在同条目下注明关联与差异，不另起 @名。
4. 合并后逐条核对无关键信息缺失即可，不再跑 face standard 校验。

## 变体形态自动抽取（2026-10-12 起 · 报告层内建）

**目标**：报告层触发时，形态抽取不再作为独立补表步骤，而是和报告一次产出。
每主角色都要有形态条目；若 `character-forms.md` 缺失，报告层要先产出一版雏形表，再继续渲染 HTML。
核心/重要角色必须有可复现的变体差异，不硬凑条目。

**判定信号仍以可见差异为准**：
- 服装/整体造型换件
- 妆容/发型/外观发生明显变化
- 伤势或身体状态发生可见变化（如裹伤、赤足、湿透、手臂骨折）
- 年龄阶段/身份状态发生可见变化（如少年→成年、总裁→破产/落魄/重病）

**报告层关联**：
- 报告层运行即产出/刷新 `assets/character-forms.md`，不再靠单独补表。

1. **只读事实来源**
    - 形态必须从 `scripts/<剧名>/script/ep*.txt` 逐件抽取。
    - xlsx 资产清单、旧 prompt 库、其他 AI 的结论只可作复核，不可替代剧本证据。
2. **先建扫描表**
    每个主角色都要先产出：
    - 集数 / 场次
    - 剧本原文关键词（短句）
    - 形态类别（服装/造型、状态/身份、伤势/身体状态、年龄/身形）
    - 可见变化点
    - 是否合并
3. **只在四类信号下才另立形态**
    - 服装/整体造型换件
    - 妆容/发型/外观发生明显变化
    - 伤势或身体状态发生可见变化（如裹伤、赤足、湿透、手臂骨折）
    - 年龄阶段/身份状态发生可见变化（如少年→成年、总裁→破产/落魄/重病）
4. **合并规则**
    - 同一句剧本反复提及同一状态，算一个形态。
    - 同一角色在同一场景/连续镜头里被写成近义说法（如高定西装、白色西装、总裁西装），
      若没有明确另有换装，合并为一件。
    - 同一角色在不同集但处于同一类状态（如同一套病号服、同一套破产素白、
      同一个KTV制服），合并为一个形态并标集数范围。
    - 情绪、剧情、动机本身不算形态；只有它造成可见妆造/伤势/道具/身份改变才算。
5. **输出前自检**
    - 每个形态都要能落到一句剧本原文或可直接识别的事件，不推定未写的五官/肤色/发型/身高。
    - 报总数时分开给：**服装/造型 X 种**、**可见状态/身份形态 Y 种**，不把两者混成一个数字。
    - 生成 `character-prompts.md` 前先按此形态清单确定条目，不按“资产表有几条就写几条”。

## 形态清单落盘规范（2026-10-12 起）

1. 「人物形态扫描与计数」结果统一落盘到 `assets/character-forms.md`；报告层复用时增量保留，
   只在新增剧本证据到位时合并或修订对应条目，不整体覆盖旧表。
2. 文件按主角色分节，每条形态按「集数 / 场次 / 剧本原文关键词 / 形态类别 / 可见变化点 /
   是否合并」逐行列出；节末分项计数：服装/造型 X 种、可见状态/身份形态 Y 种。
3. `character-forms.md` 是后续提示词条目拆分和报告层形态统计的唯一依据；统计时只引用本文件，
   不现场估数。

## 接续

- 场景/道具库同法：`scene-prompts.md`（一个场景一条独立提示词）、`prop-prompts.md`。
- 分镜阶段只准引用资产库里已登记的 `@引用名`，分镜师不得自造。
